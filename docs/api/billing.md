# Billing

## `BillingController` (no path prefix — full paths on each method)

*Owner: `account-service`.*

| Method | Path | Request | Response | Notes |
|---|---|---|---|---|
| GET | `/api/plans` | — | `List<PlanResponse>` | **Public**, no session needed — the pricing page works signed out. `price` is preformatted server-side (`util.MoneyFormat`, Indian digit grouping for INR). |
| GET | `/api/me/subscription` | — | `SubscriptionResponse` | Never a null plan — no subscription (or none currently entitling, e.g. a PAST_DUE past its grace window) returns the seeded Free plan with `isFree: true`. `syncPending: true` means a plan-change's write to Stripe succeeded but the read-back to confirm it locally failed — the fields above may still be the pre-change state; poll again rather than treating 200 as proof the change is fully reflected. |
| POST | `/api/payments/checkout` | `{ planId }` | `{ checkoutUrl }` | 400 if the caller already has a subscription (use `change-plan` instead). Idempotent: a retried request for the same plan (double click, parallel tab) reuses the same in-flight Stripe Checkout Session and idempotency key (`CheckoutIntent`) rather than minting a second one. |
| POST | `/api/payments/portal` | — | `{ portalUrl }` | 400 if the caller has never checked out. |
| POST | `/api/payments/confirm` | `{ sessionId }` | `SubscriptionResponse` | Called by the frontend on Stripe's redirect back — Stripe can't reach `localhost` webhooks in dev, so this is both a local-dev necessity and a safety net for a dropped webhook in production. Verifies the session was paid **and** its `user_id` metadata matches the caller. Idempotent, safe to race the webhook — `stripe_subscription_id`'s uniqueness constraint makes double activation a no-op rather than a duplicate row. |
| POST | `/api/payments/change-plan` | `{ planId }` | `SubscriptionResponse` | Changes an existing subscription in place — to Free cancels at period end; to the current plan while cancelling, resumes; a dearer plan charges the prorated difference now (a declined card leaves the plan unchanged, **and nothing else does either** — the cancellation-clear and the price change are one atomic Stripe update, 400 on decline); a cheaper plan credits the difference to the next invoice. |
| POST | `/webhooks/payment` | raw body + `Stripe-Signature` | 200, or 400 | No session, no CSRF (it can carry neither) — signature-verified instead, with a 300 s timestamp tolerance. A bad or missing signature, or a stale timestamp, is 400 so Stripe doesn't retry something that can never verify; an event type nothing handles is a 200. Every delivery is claimed by Stripe's own event id (`WebhookEventRepository`) before its handler runs, so a redelivered event is skipped once already fully processed, and a delayed/out-of-order event is dropped by `SubscriptionServiceImpl`'s `lastEventAt` check rather than regressing state a newer event already applied. A handler that throws leaves the event reclaimable and this endpoint returns non-2xx so Stripe retries. |
