# Architecture

- Base package: `com.java.vibecraft`
- Entry point: `VibecraftApplication` (`src/main/java/com/java/vibecraft/VibecraftApplication.java`)
- Config: `src/main/resources/application.yaml` (no more `data.sql` — deleted 2026-04-26).
- `entity` — the 11 JPA entities described above (plus `ProjectMemberId`/`ChatSessionId` composite-key classes). `User` also implements Spring Security's `UserDetails`.
- `enums` — the 5 domain enums described above.
- `config` — `PaymentConfig` (2026-05-02) sets the Stripe SDK's static `Stripe.apiKey` at startup; `StorageConfig`/`AiConfig` (both 2026-05-16) build the `MinioClient` and `ChatClient` beans respectively.
- `llm` (new 2026-05-16) — `PromptUtils` (the code-generation system prompt), `LlmResponseParser` (XML-tag output → `ChatEvent` rows), `llm.tools.CodeGenerationTools` (the `read_files` tool), `llm.advisors.FileTreeContextAdvisor` (injects the file tree into context) — see the Practices note above for how these fit together.
- `repository` — `ProjectRepository`, `ProjectMemberRepository`, `UserRepository`, `PlanRepository`, `SubscriptionRepository`, and (new 2026-05-16) `ChatEventRepository`, `ChatSessionRepository`, `ChatMessageRepository`, `UsageLogRepository`, `ProjectFileRepository` (Spring Data JPA). Only `Preview` has no repository yet.
- `mapper` — `ProjectMapper`, `ProjectMemberMapper`, `UserMapper`, `SubscriptionMapper` (2026-05-02), and (new 2026-05-16) `ProjectFileMapper`, `ChatMapper` (MapStruct) — 6 of 11 entities (`Plan`, `ChatSession`, `ChatEvent`, `Preview`, `UsageLog` don't have one). `ProjectFileMapper` gained an explicit `toFileNode` method with `@Mapping(target = "modifiedAt", source = "updatedAt")` 2026-05-24 — the list-mapping method delegates to it per element, which is how a name-mismatched field gets mapped instead of silently staying null.
- `util` (new 2026-05-24) — `ContentTypeUtils.determineContentType(path)`, shared by `ProjectFileServiceImpl` and `ProjectTemplateServiceImpl` so both file-save paths derive the same MIME type from a path the same way.
- `error` — `ApiError`, `GlobalExceptionHandler`, `ResourceNotFoundException`, `ForbiddenException`, `BadRequestException`, and (new 2026-05-16, later pass) `FileStorageException` (→ 503) — centralized exception→HTTP-response handling.
- `security` — `WebSecurityConfig` (`@Configuration`, defines the `SecurityFilterChain`/`PasswordEncoder`/`AuthenticationManager` beans), `JwtAuthFilter` (`OncePerRequestFilter`, populates the `SecurityContext` from a `Bearer` token), `AuthUtil` (JWT generate/verify + `getCurrentUserId()`), `JwtUserPrincipal` (the JWT-derived principal record).
- `controller` — 7 REST controllers: `AuthController`, `ProjectController`, `ProjectMemberController`, `FileController`, `BillingController`, `UsageController`, and (new 2026-05-16) `ChatController` (see [APIs](../api/README.md#apis) above). `BillingController` gained a 7th method, the `/webhooks/payment` handler, on 2026-05-02.
- `service` — 11 service interfaces (`FileService` deleted 2026-05-16, later pass; `ProjectTemplateService` added the same pass, never previously documented despite existing as uncommitted work), one (or two, for auth) per controller, plus the gateway-facing `PaymentProcessor` (2026-05-02) and (2026-05-16) `ProjectFileService`/`AiGenerationService` (both internal to the chat feature, not 1:1 with a controller). `TemplateInitResult` (plain record: `copiedCount`/`skippedCount`/`failedPaths`, `isComplete()`) sits alongside the interfaces as `ProjectTemplateService.initializeProjectFromTemplate`'s return type.
- `service.impl` — an `@Service` implementation of each interface above. `ProjectServiceImpl`, `ProjectMemberServiceImpl`, `AuthServiceImpl`, `SubscriptionServiceImpl`, `StripePaymentProcessor`, `ChatServiceImpl`, `AiGenerationServiceImpl`, `ProjectFileServiceImpl`, and `ProjectTemplateServiceImpl` are all fully implemented; `UserServiceImpl` implements `UserDetailsService.loadUserByUsername` for real but its own `UserService.getProfile()` is still a stub; `UsageServiceImpl` is half-real (`recordTokenUsage` only); `PlanServiceImpl` is still entirely stub (`FileServiceImpl` deleted 2026-05-16, later pass — `FileController` now uses `ProjectFileServiceImpl` directly).
- `dto` — request/response records, one subpackage per domain (`auth`, `project`, `member`, `subscription`, and new 2026-05-16 `chat`). File DTOs (`FileNode`, `FileContentResponse`, `FileTreeResponse`) live under `dto.project`, not a separate `dto.file` package.
