# Architecture

- Base package: `com.java.vibecraft`
- Entry point: `VibecraftApplication` (`src/main/java/com/java/vibecraft/VibecraftApplication.java`)
- Config: `src/main/resources/application.yaml` (no more `data.sql` — deleted 2026-04-26).
- `entity` — the 11 JPA entities described above (plus `ProjectMemberId`/`ChatSessionId` composite-key classes). `User` also implements Spring Security's `UserDetails`.
- `enums` — the 6 domain enums described above (`ProjectRole`, `ProjectPermission`, `MessageRole`, `ChatEventType`, `PreviewStatus`, `SubscriptionStatus`).
- `config` — `PaymentConfig` (2026-05-02) sets the Stripe SDK's static `Stripe.apiKey` at startup; `StorageConfig`/`AiConfig` (both 2026-05-16) build the `MinioClient` and `ChatClient` beans respectively (`AiConfig` registers `SimpleLoggerAdvisor` as a default advisor, which `application.yaml`'s `logging.level.org.springframework.ai.chat.client: DEBUG` turns into full prompt/response logs for every AI call — useful locally, but it logs whatever the user typed); `CorsConfig` exposes the `CorsConfigurationSource` bean Spring Security's CORS handling actually reads (fixed 2026-05-24, later pass — see [Practices / Conventions](../practices/conventions.md#practices--conventions) for what was wrong with it before).
- `llm` (new 2026-05-16) — `PromptUtils` (the code-generation system prompt), `LlmResponseParser` (XML-tag output → `ChatEvent` rows), `llm.tools.CodeGenerationTools` (the `read_files` tool), `llm.advisors.FileTreeContextAdvisor` (injects the file tree into context) — see the Practices note above for how these fit together. Added 2026-05-30: `AiUsageRecorder` (bills one-shot AI calls to the caller's daily usage), `ProjectNameGenerator` (names a project from its idea), `CodeInsightPrompts` (the read-only code-insight prompts, kept apart from `PromptUtils`), and `TeachingMode` (whether a turn teaches, plus the concepts already taught).
- `repository` — `ProjectRepository`, `ProjectMemberRepository`, `UserRepository`, `PlanRepository`, `SubscriptionRepository`, (new 2026-05-16) `ChatEventRepository`, `ChatSessionRepository`, `ChatMessageRepository`, `UsageLogRepository`, `ProjectFileRepository`, and (new 2026-06-03) `CodeNoteRepository` (Spring Data JPA) — 11 of 12 entities; only `Preview` has no repository yet. Every `CodeNoteRepository` method takes the user as well as the project, deliberately: a find-by-project-alone would hand one member another's notes.
- `mapper` — `ProjectMapper`, `ProjectMemberMapper`, `UserMapper`, `SubscriptionMapper` (2026-05-02), and (new 2026-05-16) `ProjectFileMapper`, `ChatMapper`, and (new 2026-06-03) `CodeNoteMapper` (MapStruct) — 7 of 12 entities (`Plan`, `ChatSession`, `ChatEvent`, `Preview`, `UsageLog` don't have one). `CodeNoteMapper`'s conversion is hand-written in `default` methods rather than generated: the entity stores the selection as four flat columns while the DTO nests it, and "all four are null" has to become one absent selection rather than an object full of nulls — a decision, not a field-name match. `ProjectFileMapper` gained an explicit `toFileNode` method with `@Mapping(target = "modifiedAt", source = "updatedAt")` 2026-05-24 — the list-mapping method delegates to it per element, which is how a name-mismatched field gets mapped instead of silently staying null.
- `util` (new 2026-05-24) — `ContentTypeUtils.determineContentType(path)`, shared by `ProjectFileServiceImpl` and `ProjectTemplateServiceImpl` so both file-save paths derive the same MIME type from a path the same way; `CodeSearchScanner` (2026-05-30), the storage-free line matcher behind code search.
- `error` — `ApiError`, `GlobalExceptionHandler`, `ResourceNotFoundException`, `ForbiddenException`, `BadRequestException`, and (new 2026-05-16, later pass) `FileStorageException` (→ 503) — centralized exception→HTTP-response handling.
- `security` — `WebSecurityConfig` (`@Configuration`, defines the `SecurityFilterChain`/`PasswordEncoder`/`AuthenticationManager` beans), `JwtAuthFilter` (`OncePerRequestFilter`, populates the `SecurityContext` from a `Bearer` token), `AuthUtil` (JWT generate/verify + `getCurrentUserId()`), `JwtUserPrincipal` (the JWT-derived principal record).
- `controller` — 10 REST controllers: `AuthController`, `ProjectController`, `ProjectMemberController`, `FileController`, `BillingController`, `UsageController`, (new 2026-05-16) `ChatController`, (new 2026-05-30) `IdeaController` and `CodeInsightController`, and (new 2026-07-15, split out of `AuthController` when Firebase sessions became the primary path) `LegacyAuthController`. `BillingController` gained a 7th method, the `/webhooks/payment` handler, on 2026-05-02.
- `service` — 14 service interfaces (`IdeaService` and `CodeInsightService` added 2026-05-30; `FileService` deleted 2026-05-16, later pass; `ProjectTemplateService` added the same pass, never previously documented despite existing as uncommitted work), one (or two, for auth) per controller, plus the gateway-facing `PaymentProcessor` (2026-05-02) and (2026-05-16) `ProjectFileService`/`AiGenerationService` (both internal to the chat feature, not 1:1 with a controller). `TemplateInitResult` (plain record: `copiedCount`/`skippedCount`/`failedPaths`, `isComplete()`) sits alongside the interfaces as `ProjectTemplateService.initializeProjectFromTemplate`'s return type.
- `service.impl` — an `@Service` implementation of each interface above. `ProjectServiceImpl`, `ProjectMemberServiceImpl`, `AuthServiceImpl`, `SubscriptionServiceImpl`, `StripePaymentProcessor`, `ChatServiceImpl`, `AiGenerationServiceImpl`, `ProjectFileServiceImpl`, `ProjectTemplateServiceImpl`, `UserServiceImpl` (profile real since 2026-05-24), `UsageServiceImpl` (all three methods real since 2026-05-24), `IdeaServiceImpl` and `CodeInsightServiceImpl` (both 2026-05-30) are all fully implemented; `PlanServiceImpl` is still entirely stub (`FileServiceImpl` deleted 2026-05-16, later pass — `FileController` now uses `ProjectFileServiceImpl` directly).
- `dto` — request/response records, one subpackage per domain (`auth`, `project`, `member`, `subscription`, new 2026-05-16 `chat`, and new 2026-05-30 `idea` and `code` — the latter holding both the code-search and code-insight DTOs). File DTOs (`FileNode`, `FileContentResponse`, `FileTreeResponse`) live under `dto.project`, not a separate `dto.file` package.
