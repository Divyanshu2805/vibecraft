# Common Problems

| Symptom | Cause | Fix |
|---|---|---|
| `./mvnw test` fails outright, `contextLoads`/any `@SpringBootTest` won't start | Windows JVM reports the legacy `Asia/Calcutta` timezone alias; PostgreSQL's JDBC driver rejects it. `VibecraftApplication.main()` fixes this via `TimeZone.setDefault(...)`, but Spring's test infrastructure calls `SpringApplication.run(...)` directly, bypassing `main()` entirely | Run named test classes (`-Dtest=...`) instead of the bare suite. If you genuinely need a passing `@SpringBootTest`: `./mvnw test -Dtest=SomeTest "-DargLine=-Duser.timezone=Asia/Kolkata"`, and use the default `MOCK` web environment (`WebEnvironment.NONE` fails — `SessionAuthFilter` needs a `HandlerExceptionResolver`, which only exists with MVC) |
| `spring-boot:run` (or a Claude Code `preview_start` targeting port 8080) fails to bind | Some sandboxes/CI runners treat 8080 as an OS-excluded port range | Run `./mvnw spring-boot:run` directly with `--server.port=<other>` rather than through a tool that assumes 8080 |
| Cross-origin requests rejected outright, no useful error | A `@Configuration`/`@Component`/`@Service` class sits outside `com.java.vibecraft`'s component-scan root — Spring silently never registers it as a bean, no error or warning anywhere. Happened once already with `CorsConfig` (a leftover from the reference project this was adapted from) | If a bean's effect just isn't happening with no error, check its package declaration matches its directory, not just that the file compiles |
| `@PreAuthorize` denies a legitimate caller | The SpEL parameter name doesn't exactly match the method's actual parameter name (`#projectId` used, but the method's parameter is `id`) — this fails **silently**, evaluating to `null`/deny, not a startup or compile error. Has happened three separate times in this codebase | Double-check the parameter name character-for-character whenever adding a new `@PreAuthorize` annotation |
| `No qualifying bean` at startup for a class that has a `@Value` field | Lombok's `@FieldDefaults(makeFinal = true)` + `@RequiredArgsConstructor` sweeps the now-final `@Value` field into the generated constructor as a plain parameter — but doesn't carry the `@Value` annotation over, so Spring tries to autowire it as a bean instead of resolving a property | Exempt that one field with `@lombok.experimental.NonFinal`, or keep the class's `@Value` fields off the Lombok-generated constructor entirely (`AuthUtil`'s approach) |
| A newly-added enum value fails every insert with a DB constraint error, no compile-time warning | `ddl-auto: update` never widens a `CHECK` constraint Hibernate already generated for an `@Enumerated(STRING)` column | See `docs/schema/`'s "Persisted enums and the `ddl-auto` trap" — check `\d <table>` after any persisted-enum change |
| Chat history comes back empty after a turn that clearly generated files | The event batch failed to save (often the enum trap above) while the file-save step (a separate, more resilient path) succeeded | Check the backend log for a WARN around `chat_events` — `finalizeChats` falls back to saving events one at a time, so a full-batch failure usually still saves *most* of them |
| A `.ts`/`.tsx` project file shows the wrong MIME type / renders oddly in the UI | `java.net.URLConnection.guessContentTypeFromName` maps `.ts` to an MPEG Transport Stream video type by default | `util.ContentTypeUtils` overrides this — if you see it regress, check the override runs *before* the JDK guesser, not after |
| MinIO SDK classes fail to resolve at compile time (`cannot access okhttp3.HttpUrl`) | `io.minio:minio` pulls in a near-empty, Gradle-only-metadata `okhttp:5.1.0` by default | `okhttp:4.12.0` is pinned explicitly in `pom.xml` — don't let it resolve transitively |
| A preview never starts, stuck at "Starting a runner" | Every pod in the warm pool is busy (`CapacityUnavailableException`, 503) or the Kubernetes cluster/Redis aren't reachable at all | `kubectl -n vibecraft-ai get pods` to check pool state; confirm the port-forwards from [Running Live Previews Locally](live-previews.md#running-live-previews-locally) are actually up |
| `legacy-monolith` fails to boot with `NoClassDefFoundError: io/fabric8/kubernetes/client/V1Alpha1AdmissionRegistrationAPIGroupDSL` after touching root `pom.xml` | `spring-cloud-dependencies` separately manages `io.fabric8:kubernetes-client-api` at a version (7.4.1, for Spring Cloud Kubernetes' own starters, unused here) that doesn't match `kubernetes-client` 6.13.4 pinned in `legacy-monolith/pom.xml` — a mismatched pair of fabric8 jars compiles fine (only `KubernetesClientBuilder.build()` touches the missing class) and fails only at runtime | The root `pom.xml` imports `io.fabric8:kubernetes-client-bom:6.13.4` in `dependencyManagement` *before* `spring-cloud-dependencies`, so it wins for every fabric8 coordinate — don't reorder those two imports, and re-run `./mvnw -pl legacy-monolith dependency:tree -Dincludes=io.fabric8` after touching either BOM's version to confirm every fabric8 artifact still resolves to the same version |
| `./mvnw -pl legacy-monolith spring-boot:run` can't find `.env` / boots with blank secrets | `legacy-monolith` moved from the repo root into its own module directory; Maven's default working directory for a forked `spring-boot:run` process is the module's own directory, not the reactor root, but `.env` still lives at the repo root | Already handled — `legacy-monolith/pom.xml`'s `spring-boot-maven-plugin` sets `workingDirectory` to the parent (repo root) explicitly. If you ever see this, check that config wasn't accidentally removed |
