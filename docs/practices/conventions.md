# Practices / Conventions

- Maven Wrapper (`mvnw`/`mvnw.cmd`) used instead of a system Maven install.
- Empty POM overrides (`name`, `description`, `url`, `license`, `developers`, `scm`) to avoid inheriting values from `spring-boot-starter-parent`.
- Lombok wired as an annotation processor in both compile and test-compile Maven executions; entities consistently use `@Getter @Setter @FieldDefaults(level = AccessLevel.PRIVATE) @AllArgsConstructor @NoArgsConstructor @Builder`.
- `@CreationTimestamp`/`@UpdateTimestamp` (Hibernate) for automatic `createdAt`/`updatedAt` timestamps, instead of manual `@PrePersist`/`@PreUpdate` methods.
- Composite primary keys (`ProjectMember`, `ChatSession`) modeled via `@EmbeddedId` + `@MapsId`, with a small dedicated `@Embeddable`, `Serializable` ID class (`ProjectMemberId`, `ChatSessionId`) per entity — each carries `@EqualsAndHashCode` over its fields, required by the JPA spec for composite keys to behave correctly in the persistence context.
- Soft delete via a plain nullable `deletedAt` timestamp column (`User`, `Project`, `ChatSession`) — no delete-filtering annotation (`@SQLDelete`/`@Where`) wired up yet, so exclusion of soft-deleted rows must currently be done manually in queries.
- Role-based access via a plain `ProjectRole` enum (`EDITOR`, `VIEWER`, `OWNER`) on `ProjectMember` — project ownership is itself just a role value (`projectRole = OWNER`), not a separate FK on `Project`. `ProjectServiceImpl.createProject` creates the owner's `ProjectMember` row in the same request that creates the `Project`.
- Repositories are Spring Data JPA interfaces (`repository.XRepository extends JpaRepository<X, IdType>`) with `@Query` JPQL for anything beyond CRUD (e.g. `ProjectRepository.findAllAccessibleByUser`) — added per-entity only as a service actually needs one, not upfront for all 10 entities.
- Entity→DTO mapping is via MapStruct (`mapper.XMapper`, `@Mapper(componentModel = "spring")`) rather than hand-written conversion code; `@Mapping(target, source)` is only needed when the entity and DTO field names differ (MapStruct auto-matches identically-named properties, including nested objects, without any annotation).
- A single `GlobalExceptionHandler` (`@RestControllerAdvice` in the `error` package) centralizes exception→HTTP-response translation, returning a shared `ApiError` record — add new `@ExceptionHandler` methods there rather than handling errors per-controller.
- Local dev history tracked in `DEVLOG.md` (gitignored); this file is the tracked, public-facing project doc.
- Semantic, one-line commit messages (`feat:`, `fix:`, `docs:`, `chore:`, etc.).
- Request/response DTOs are Java `record`s, one subpackage per domain under `dto`. **Request** DTOs carry Bean Validation constraints (`@NotBlank`, `@Email`, `@Size`, `@NotNull`), every constraint with an explicit `message = "..."`, and the controller parameter is annotated `@RequestBody @Valid`. **Response** DTOs never carry validation annotations — they're server output, not input to reject.
- Services are defined as plain interfaces (`service.XService`) with implementations in a separate `service.impl` package (`XServiceImpl`, `@Service`) — controllers depend only on the interface via `@RequiredArgsConstructor`. Implementations were initially added as stubs (every method returns `null`/empty/no-op) just to satisfy Spring's dependency injection and let the app boot; real logic is filled in incrementally per method (`ProjectServiceImpl.createProject`/`getUserProjects` are the first two done for real — repository lookup, `ResourceNotFoundException` on a missing user, MapStruct for the entity→DTO conversion).
- Controllers consistently use `@RequiredArgsConstructor` for constructor injection; `AuthController` additionally uses `@FieldDefaults(makeFinal = true, level = AccessLevel.PRIVATE)` on its fields (the other controllers just declare fields `private final` directly — not yet made consistent across all controllers).
- The JVM's default timezone is forced to `Asia/Kolkata` at the top of `main()` (`VibecraftApplication`) — on some Windows JVMs, `TimeZone.getDefault()` returns the legacy alias `"Asia/Calcutta"`, which the PostgreSQL JDBC driver sends as a connection startup parameter; PostgreSQL only recognizes the modern IANA name `"Asia/Kolkata"` and rejects the connection otherwise (`FATAL: invalid value for parameter "TimeZone"`).
- `application.yaml` and `data.sql` are both committed. Datasource credentials use Spring property placeholders with a local-dev fallback (`${DB_USERNAME:User}`, `${DB_PASSWORD:Password}`) rather than being hardcoded — this repo is public, so real credentials should come from environment variables, not from editing the committed defaults.
