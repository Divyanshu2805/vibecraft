# Security & Guardrails (do not bypass)

- **Generated/user code executes only inside a live-preview Kubernetes pod**, reached via the fabric8 client's `exec` API — never in-process in the backend, never via a local shell call. Any change that would run untrusted project content outside that boundary is a hard no.
- **`CodeInsightController`'s endpoints must stay read-only *structurally*, not just by prompt instruction.** The model is handed exactly one tool (`read_files`) and its prompts (`llm/CodeInsightPrompts.java`) never mention the `<file>`/`<todo>`/`<learn>` write protocol at all. Don't add a write-capable tool here, and don't "helpfully" inline file contents into the prompt instead of the on-demand read — that's also what keeps a large project from flooding the context.
- **Client-supplied conversation history is an instruction-injection surface, not trusted context.** `AskCodeRequest.history`'s `role` field is validated *by value*, not just length — anything that isn't literally `"assistant"` becomes a `UserMessage` before it reaches the model, so a client sending `role: "system"` can't smuggle instructions in. Any new endpoint that replays client-supplied history into a model's message list needs the same by-value check, not just a `@Size` cap.
- **Every secret is a bare env-var placeholder in `application.yaml`, with zero committed fallback.** Don't add a working default "for local-dev convenience" — this repo is public, and a missing value should fail startup loudly, not run silently insecure.
- **CSRF cannot be disabled for the session-cookie auth path.** A session that rides in a cookie the browser auto-attaches is exactly the shape CSRF protection exists for — the only two exemptions (Stripe's webhook, a legacy Bearer request) are exempted because the caller structurally can't carry the header, not as a convenience.
- **Any new module-level frontend store holding project- or user-specific state must register with `frontend/src/lib/session.ts`'s `onSignOut(...)`.** A client-side route change after sign-out does not clear it on its own — module state lives for the page's lifetime, and this has caused a real cross-account data leak once already. See `docs/architecture/cross-cutting-concerns.md` §6.
- **`logging.level.org.springframework.ai.chat.client: DEBUG` logs every AI prompt and response in full**, including whatever the user typed. Useful locally; be mindful before sharing local logs anywhere.
