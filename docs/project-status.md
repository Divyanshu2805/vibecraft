# Project Status

_Last updated: 2026-04-26._

| Area | Status |
|---|---|
| Domain entities | 10 entity types (see [Entities / Models](schema/README.md#entities--models)) — schema is now **v4**. Project ownership moved back onto `ProjectMember.projectRole == OWNER` (no `Project.owner` FK — this reverses v3's change, see [Differences from v3](schema/README.md#differences-from-v3)), and `User`'s `email`/`passwordHash` were renamed back to `username`/`password` with `avatarUrl` dropped (also reversing v3). `ChatMessage` still stores tool calls as a `toolCalls` JSON string, and `UsageLog` is still a per-action audit row (those two v3 changes stand). |
| Repositories | 3 exist: `ProjectRepository` (`findAllAccessibleByUser`, `findAccessibleProjectById` — both now join `ProjectMember` rather than filtering on `Project.owner`), `ProjectMemberRepository` (`findByIdProjectId`), `UserRepository` (`findByUsername`, plus CRUD). The other 7 entities have no repository yet. |
| Mapper | 2 exist: `ProjectMapper` (`Project` → `ProjectResponse`/`ProjectSummaryResponse`), `ProjectMemberMapper` (`User`/`ProjectMember` → `MemberResponse`, MapStruct). No mapper for any other entity yet. |
| Error handling | `GlobalExceptionHandler` (`@RestControllerAdvice`) handles three exception types: `ResourceNotFoundException` → 404, `ForbiddenException` → 403, `MethodArgumentNotValidException` → 400 with a per-field `errors` list (all mapped to the shared `ApiError`, whose `errors` field is only included in the JSON response when non-null). A plain `RuntimeException` thrown directly (see `ProjectMemberServiceImpl.removeProjectMember` below) still isn't caught, so it surfaces as a 500. |
| Services / business logic | 2 of 8 services are now fully implemented — `ProjectServiceImpl` (`createProject`, `getUserProjects`, `getUserProjectById`, `updateProject`, `softDelete`) and `ProjectMemberServiceImpl` (`getProjectMembers`, `inviteMember`, `updateMemberRole`, `removeProjectMember`). Every method across the other 6 services is still a stub (`null`/empty/no-op). |
| REST APIs | 6 controllers implemented — see [APIs](api/README.md#apis) below. All still hardcode `Long userId = 1L` in place of a real authenticated principal. |
| Database | PostgreSQL datasource configured in `application.yaml` (committed), `ddl-auto: create` (switched from `update` on 2026-04-26 — drops and recreates the whole schema, plus reseeds `data.sql`, on every startup; convenient while the entity shapes are actively changing, but be aware it wipes local data on every restart). Credentials are `${DB_USERNAME:User}`/`${DB_PASSWORD:Password}` env-var placeholders with a local-dev fallback, not hardcoded. `data.sql` seeds 3 dummy `User` rows (`id=1` Divyanshu, `id=2` Anuj, `id=3` Shivam), each with `password = 'N/A'` (placeholder — real password hashing isn't implemented yet), on every startup (`ON CONFLICT DO NOTHING`, so it's idempotent) — the extra two exist so `ProjectMemberService.inviteMember` has other real users to invite by username locally. |
| Tests | Only the generated `contextLoads` smoke test |

**Next up:** replace the remaining service stubs with real logic — `AuthServiceImpl`/`UserServiceImpl` first (password hashing, token generation), since nothing else is reachable without real login. Real authentication should also replace the `userId = 1L` placeholder in every controller. **Known gaps, most severe first:** (1) **all owner-only authorization was dropped** when ownership moved onto `ProjectMember.projectRole == OWNER` — `ProjectServiceImpl.updateProject`/`softDelete` and `ProjectMemberServiceImpl.inviteMember` now only check that the caller is *some* project member (any role, via `getAccessibleProjectById`), not specifically the owner; `ProjectMemberServiceImpl.updateMemberRole`/`removeProjectMember` don't call `getAccessibleProjectById` at all any more, so they don't check project membership *or* ownership — any caller who knows a `projectId`/`memberId` pair can currently change roles or remove members on a project they don't belong to. This needs an explicit owner check (`projectMember.getProjectRole() == ProjectRole.OWNER`) restored in all four methods before this is safe. (2) `removeProjectMember` throws a plain `RuntimeException` for "member not found" instead of `ResourceNotFoundException`, so it currently surfaces as a 500 instead of a 404, unlike every other "not found" path in the codebase. (3) `LoginRequest.password`'s `@Size(min = 8)` (see [Request Validation](api/README.md#request-validation)) has no `message`, breaking the "every constraint has an explicit message" convention every other constraint in the codebase follows.
